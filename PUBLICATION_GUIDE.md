# GitHub and LinkedIn preparation for ModernizeIQ

## Before publishing

1. Run the app and the tests yourself. Keep the test output.
2. Change one sample and predict the outcome before running it.
3. Add one meaningful negative test or documented feature. Record your exact contribution.
4. Remove local databases, personal data, credentials and dependency folders. Do not upload your résumé PDF or private notes with source code.
5. Review the license, README and limitations. Do not describe the sandbox as production deployed or claim customer adoption.
6. Create a separate GitHub repository. From the project folder: `git init`, `git add .`, `git commit -m "Add tested local baseline"`, `git branch -M main`. Add your own repository URL using `git remote add origin YOUR_REPOSITORY_URL`, then `git push -u origin main`. These commands are instructions; nothing was published on your behalf.

## Résumé framing

Your existing Python, SQL, automation and data-analysis experience is a foundation; these new applications are not proof of advanced proficiency until you can operate, modify and explain them. Use at most two projects you can defend deeply rather than listing four unfamiliar systems. State assistance honestly when asked.

Suggested project line after completing your own experiment: “Built and extended a local ModernizeIQ prototype with FastAPI, SQLite, validated inputs and regression tests; implemented [your specific change] and verified [your measured outcome].”

## Interview checklist

Explain the problem in 30 seconds, trace one request through the code in two minutes, demonstrate a failure, identify one limitation, and show a test you wrote yourself. The important evidence is your understanding and contribution, not a readiness score.
